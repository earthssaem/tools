# 움짤 메이커

웹앱(시뮬레이션, 탐구실)을 녹화해서 네이버 블로그 소개 글에 올릴 GIF를 기능별로 여러 개 뽑는 도구입니다.
한 번 녹화 → 구간 표시 → 저장. 프리셋·크기·프레임 수는 자동으로 정합니다.

**모든 처리는 브라우저 안에서만 이루어집니다.** 녹화한 영상과 만든 GIF를 서버로 보내지 않고 어디에도 저장하지 않습니다. 새로 고치거나 창을 닫으면 모두 사라집니다. 데스크톱 크롬 기준입니다.

## 기능

- **입력**: 크롬 탭·창 녹화(커서 포함, 최대 5분), mp4·webm·mov 불러오기
- **편집**: 영역 자르기(전체 또는 구간별, 비율 고정), 구간 표시(`I` 시작 · `O` 끝 · `Space` 재생 · `←→` 1프레임), 구간 안 2·4배속, 마지막 장면 멈춤, 왕복 재생
- **자동 설정**: 구간마다 화면 변화율을 재서 시뮬레이션형/탐구실형을 정하고 근거를 보여 줍니다.
- **출력**: 앞 2초로 예상 용량을 어림하고, 목표 용량(19·10·5MB)을 넘으면 프레임 수 → 가로 크기 순으로 줄여 다시 만듭니다. 구간별 저장, ZIP 전체 저장, webp 보조 출력.

## 구성

정적 파일만으로 동작합니다. 빌드 과정이 없습니다.

```
index.html              화면과 모든 동작 (녹화, 편집, 자동 판별, 변환, 저장)
icon.svg                도구 목록 페이지에 나오는 아이콘
lib/ffmpeg-0.12.15/     ffmpeg.wasm 래퍼
lib/core-mt-0.12.10/    ffmpeg core 멀티스레드 빌드 (약 32MB)
lib/core-0.12.10/       ffmpeg core 싱글스레드 빌드 (약 32MB)
```

- 라이브러리는 저장소에 직접 넣었습니다. CDN을 포함해 바깥으로 나가는 요청이 없습니다.
- `index.html`의 Content-Security-Policy가 같은 주소 밖으로 나가는 요청을 브라우저 차원에서 막습니다.
- ffmpeg core는 앱을 열 때가 아니라 첫 변환(첫 구간의 예상 용량 계산) 때 내려받습니다.
- 멀티스레드에는 저장소 루트 `vercel.json`이 `/gif/`에 넣는 `Cross-Origin-Opener-Policy`·`Cross-Origin-Embedder-Policy` 헤더가 필요합니다. 헤더가 없거나 멀티스레드가 멈추면 싱글스레드로 바꿔서 계속합니다(조금 느림).
- 두 core 빌드 모두 `libwebp_anim` 인코더가 들어 있습니다. 앱이 처음 불러올 때 한 번 더 확인하고, 없으면 webp 출력을 끕니다.
- localStorage, IndexedDB, 쿠키를 쓰지 않습니다.

## 실행

저장소 루트에서 정적 서버를 띄우고 `/gif/`를 엽니다. `index.html`을 파일로 직접 열면(`file://`) 모듈과 워커가 막혀 동작하지 않습니다.

```bash
npx serve
```

이렇게 띄우면 COOP/COEP 헤더가 없어 싱글스레드로 동작합니다. 멀티스레드까지 확인하려면 Vercel 미리보기 배포를 쓰세요.

## 조정값

`index.html` 스크립트 맨 위 `CFG`와 `PRESETS`에 모여 있습니다.

- `DIFF_THRESHOLD`(24), `SIM_RATIO`(0.25): 자동 판별 기준. 시작값이므로 실제 웹앱을 녹화해 보고 조정합니다.
- `PRESETS`: 시뮬레이션형(15fps · 720px · bayer 디더링), 탐구실형(10fps · 800px · 디더링 없음 · 끝 멈춤 1.5초)

## 한계

- 한 구간은 30초까지입니다. 목표 용량에 안 들어가면 구간을 나누거나 빨리 감기를 넣어야 합니다.
- 자막·화살표 같은 주석, 소리 녹음, mp4 출력, 여러 영상 이어 붙이기는 지원하지 않습니다.
- 하드웨어 가속이 꺼진 PC에서 녹화하면 미리보기 영상의 색이 조금 틀어져 보입니다(크롬의 녹화 방식 때문). 만든 GIF는 원래 색으로 되돌려 저장합니다.
